## 0. Коротко

**Десять главных решений.**

1. **Одно C++-ядро без ROS (`tbo_core`) плюс тонкая нода rclcpp.** Ядро уже начато: IMM-EKF по состоянию [s, v, d, k, g], 4 режима, буфер с фиксированным лагом, планировщик выходов. Офлайн-реплей гоняет тот же код. Одна нить, без аллокаций в горячем пути.
2. **Процессная модель работает как «виртуальный акселерометр».** Состав:
   - монотонная карта «позиция → ускорение» с ограничением мощности и лагом 0,3 с;
   - уклон и кривизна из нашей карты пути;
   - возмущение d как процесс Гаусса–Маркова;
   - адаптивный коэффициент тяги g.

   **[проверено]** Карта уклонов вдвое снижает дрейф модели без колёс: на горизонте 10 с RMSE скорости 1,09 → 0,60 м/с (таблица), 0,48 м/с (физическая форма).
3. **Проскальзывание ловит «знаковый» IMM** по валидности тележек (норма / передняя / задняя / обе). В тяге колесо может только **завышать**, в торможении только **занижать**, как в WSP/SCMT. Поверх IMM стоят CUSUM медленного синхронного дрейфа и монитор согласованности позиции контроллера. Модель «обвиняет» колёса только там, где это допускает физика.
4. **Позиция считается одномерно вдоль пути** по нашей RTK-карте: кольцевой граф 11 054 м плюс ответвления. Остановки работают как виртуальные балисы (ETCS). Масштаб колёс калибруется через ковариацию s–k.
   - Ожидание: вдольпутевая RMSE 2–3 м, дрейф в конце ≤ 0,05 %, поперечная ≈ точность карты (≤ 0,3 м).
5. **Масштаб колёс k оцениваем онлайн, и это обязательно (P0).** **[проверено]** В бэгах 03.09 (последняя дата записи) колёса 30618 занижают на 0,5–1,5 % против обычного 1/3,598.
   - Без калибровки это −0,08 м/с смещения скорости и 1,65 % дрейфа (бэг `30618_defd0170`).
   - k исправляет и позицию, и **скорость**.
6. **Время.** Фильтр работает по header-меткам. Окно с фиксированным лагом 1 с принимает сообщения не по порядку. Выход публикуется:
   - на метках cmd (≈ время bag);
   - на сетке 0,05 с, кратной сетке эталона 0,1 с;
   - по сторожевому таймеру при пропусках.

   Параметр `output_value_delay_s` закрывает неизвестную базу времени судьи. Цена ошибки: RMSE скорости 0,032 → 0,055 м/с и смещение ±0,05 м/с в переходах.
7. **Выходная СК задаётся конфигурируемым проектором.** По умолчанию ENU от первого фикса master, z = ENU-up, точка = антенна master. Неверный выбор стоит **до 110 м** (UTM), **12,4 м** (rover), **до 1,8 м** по z. **Вопросы организаторам — сегодня** (§6.2).
8. **GNSS используется только в окне инициализации (≤ 5 с), потом подписки уничтожаются.** **[проверено]** Трамвай в этом окне стоит во всех обучающих бэгах, поэтому скорость и масштаб из GNSS не получить. Берём только позицию на карте и курс по базе антенн (σ ≈ 0,01°).
9. **Бонусы критерия 3 публикуем в `/diagnostics`:**
   - флаг и вероятности проскальзывания по тележкам, скольжение λ_f/λ_r;
   - μ_used, μ̂_max и класс рельса;
   - g (относительная масса), k (износ колеса), d (эквивалентный уклон);
   - счётчики аномалий и задержка.
10. **Доказательства для жюри:**
    - харнесс, копирующий судью (обе гипотезы времени, режимы, вдоль/поперёк пути, NEES);
    - 20 сценариев инъекций S00–S19;
    - лестница абляций с доверительными интервалами;
    - таблица соответствия реальному времени в Docker `--cpus=2 --memory=512m`;
    - тест «GNSS вырезан после окна → выход побитово тот же».

**Целевые метрики.** Отложенная выборка, судья-копия, база времени header. Колонка «Сейчас» — базовая линия B2 из `tools/harness/results`: сырые колёса, гигиена входов, карта-оракул, 40 Гц.

### 2.2 Процессы и пакеты

- **Один процесс-нода `tram_backup_odometry_node` (C++)**, `SingleThreadedExecutor`, все колбэки в одной взаимоисключающей группе. Гонок нет по построению.
  - Разбивать на несколько нод (отдельно детектор юза, отдельно позиция) смысла нет. Это лишние DDS-переходы и синхронизация, баллов не добавляет.
- **Пакеты** (минимум, всё из ros-base):
  - `tram_vehicle_msgs` — копия из датасета.
  - `tram_backup_odometry`:
    - `core/` — библиотека без ROS; уже есть в `ros2_ws/src/tram_backup_odometry/core`;
    - нода, `launch/`, `config/*.yaml`, `maps/` (карта + ориентиры, ставятся в `share/`);
    - `scripts/latency_probe.py`, `scripts/resource_monitor.py`;
    - тесты.
  - Отдельный пакет для `EstimatorDebug.msg` — только P2. Бонусные поля полностью покрывает `diagnostic_msgs/DiagnosticArray`, который есть в `common_interfaces`, без риска для сборки.
- **Офлайн-контур.** `tbo_replay` (то же ядро: CSV/npz на входе, CSV выходов с метками) → `tools/harness` (метрики как у судьи) → `tools/anomaly_sim` (инъекции). Python-версию оценивателя не поддерживаем: источник истины — C++-ядро.

### 2.4 Инженерные инварианты (критерии 3 и 4)

- **Колбэки и ошибки.**
  - Каждый колбэк обёрнут в `guarded()` (try/catch → мягкий сброс).
  - На выход NaN не попадает: при нефинитном состоянии — мягкий сброс, а выход берётся из модели.
  - Буферы фиксированного размера, карта загружается до создания подписок.
- **QoS:** входы `KeepLast(100).best_effort()` (стартовый всплеск ~400 сообщ./с), выходы `KeepLast(10).reliable()`.
- **Часы.** Метки выходов никогда не берутся из `now()`. Таймеры только wall; `use_sim_time` принимается, но логика от него не зависит.
- **Сборка.** Тип сборки Release по умолчанию в CMakeLists (голый `colcon build` даёт -O0). Без `-Werror`. Без FetchContent, pip и `diagnostic_updater` (его нет ни в одном варианте Humble). Файлы в LF.
- **Порядок запуска для жюри:** нода запускается **до** `ros2 bag play`. Если GNSS не пришёл — относительная одометрия и WARN.

## 3. Математическая модель

### 3.1 Обозначения и единицы

| Символ | Смысл | Единицы |
|---|---|---|
| $u\in\{-15..15\}$ | Позиция контроллера: >0 тяга, <0 тормоз | — |
| $w_i^{raw}$ | Скорость тележки $i\in\{f,r\}$ из топика — **км/ч** (отношение к GNSS 3,597), хотя README пишет «м/с» | км/ч |
| $c_w$ | Перевод км/ч → м/с с калибровкой: $1/3{,}598$ (медиана парка) | (м/с)/(км/ч) |

| $s$ | Координата вдоль пути: длина дуги карты по траектории опорной антенны | м |

| $d$ | Остаточное возмущение ускорения: ошибка карты уклонов, сопротивления, ветер | м/с² |
| $k$ | Ошибка масштаба колёс: $z=(1+k)v$ | — |
| $g$ | Коэффициент реализации тяги и торможения (загрузка, масса) | — |
| $a_d$ | Реализованное ускорение привода: лаг от заданного $a^*$ | м/с² |
| $\theta(s),\kappa(s),\rho(s)$ | Уклон, кривизна, $ds_{map}/ds_{wheel}$ из карты | —, 1/м, — |

### 3.2 Нелинейная модель тягового привода

Позиция контроллера задаёт **требуемое ускорение**, а не скорость. На постоянной позиции трамвай разгоняется до ограничения мощности. Модель идентифицирована по 52 обучающим бэгам (`analysis/traction_id/physics_model_sc.json`) с лагом, по ускорению из GNSS и с картой уклонов.

**Тяга** ($u>0$), форма «sc» — доля огибающей момента и мощности:

$$a^*(u,v)=x(u)\cdot\min\!\Big(A_{max},\ \frac{P_{max}}{\max(v,0{,}1)}\Big)$$

- $x(u)$ — монотонная кусочно-линейная функция с узлами $u=1,3,5,7,10,15$ и значениями $0{,}136;\ 0{,}330;\ 0{,}569;\ 0{,}757;\ 0{,}884;\ 1$.
- $A_{max}=1{,}108$ м/с², $P_{max}=7{,}13$ м²/с³ (Вт/кг эффективной массы). Базовая скорость $P/A\approx6{,}4$ м/с = 23 км/ч, выше неё — постоянная мощность.
- В терминах момента на валу: $T=a^*\,M_{eff}\,r/(4\,i\,\eta)$, $i=6{,}921$, $r=0{,}30$ м, $\omega_{motor}=v\,i/r$. Это нужно для документации: требование кейса «момент по позиции и угловой скорости вала».

**Торможение** ($u<0$): замедление по позиции задаётся таблицей (компенсация загрузки) и угасает на малой скорости (блендинг электродинамического и механического тормоза):

$$a^*(u,v)=-D(|u|)\cdot h(v),\qquad h(v)=h_0+(1-h_0)\frac{\min(v,v_h)}{v_h},\quad h_0=0{,}48,\ v_h=2{,}5\ \text{м/с}$$

- $D(|u|)$ — монотонная (изотоническая) таблица из 15 значений. Устойчивые медианы (`research/tram_traction_model.md` §6.4): 0,15 / 0,43 / 0,58 / 0,62 / 0,66 / 0,70 / 0,83 / 0,85 / 1,03 / 1,21 / 1,30 / 1,37 / 1,44 / ≈1,5 / 1,67 м/с².
- Линейная аппроксимация $b_0+b_1|u|$ ($0{,}198+0{,}098|u|$) — запасной вариант. Выбор по многошаговой ошибке (§5).
- Нейтраль: $a^*=0$.

**Динамика привода.** Апериодическое звено первого порядка без чистого запаздывания, $\tau=0{,}30$ с, одинаковое вверх и вниз:

$$\dot a_d=\frac{g\,a^*(u,v)-a_d}{\tau}$$

**[проверено]** Раздельные τ вверх/вниз, чистое запаздывание 0,1–0,2 с и ограничитель рывка по данным не лучше: одношаговая RMSE 0,104 против 0,104–0,113 м/с². Двухполюсное звено лучше меньше чем на 1 % (0,103), усложнять не стоит.

**Качество модели** (валидация, одношаговая ошибка ускорения):

| Вариант | RMSE, м/с² |
|---|---|
| Таблица с уклонами | 0,104 |
| Таблица без уклонов | 0,142 |
| GBM-остаток | 0,072 |

Ошибка максимальна в первые 0,25 с после смены позиции (0,123 против 0,049 при удержании > 4 с) и на позициях −13…−15 (0,32–0,73: аномалии канала плюс, возможно, магниторельсовый тормоз).

### 3.3 Продольная динамика

$$\dot v=\underbrace{a_d}_{\text{привод}}-\underbrace{(c_0+c_1v+c_2v^2)}_{\text{основное сопр.}}-\underbrace{k_\theta\,\theta(s)}_{\text{уклон}}-\underbrace{k_\kappa\,|\kappa(s)|}_{\text{кривая}}+d,\qquad \dot s=\rho(s)\,v,\qquad v\ge0$$

- **Сопротивление.** Подгонка дала $c_0=0{,}049$, $c_1=0{,}0024$, $c_2=-4\cdot10^{-4}$. **Отрицательное $c_2$ нефизично**: $R(v)<0$ выше ~14,5 м/с. Перефитить с ограничением $c_2\ge0$ (априор $c_2\approx1{-}2\cdot10^{-4}$, Дэвис для 71-911ЕМ ≈ 0,085 м/с² при 54 км/ч) или зафиксировать $c_2$ по априору.
- **Уклон.** $k_\theta\approx8{,}2$ м/с² подогнано (по режимам 7,7–8,8; теоретически $g/(1+\gamma)\approx9{,}1$). Разница — сглаживание карты. **[проверено]** После ввода уклона наклон остатка по уклону почти нулевой: 0,0004 м/с² на 1 %. На маршруте уклоны до 4,1 %, то есть до 0,4 м/с² — больше основного сопротивления в 5–10 раз.
- **Кривая** (P1). Норматив СП 98.13330 даёт $w_r=500/R$ ‰, отсюда $k_\kappa\approx4{,}5$ м²/с² и 0,18 м/с² при $R=25$ м (кольца). $k_\kappa$ подогнать регрессией остатков по $|\kappa|$. Сейчас кривые в модели не учтены.
- **$\rho(s)$** (P1). Плечо антенны в кривых: антенна у торца идёт по другой дуге, чем ось пути. Колесо/GNSS = 0,992 при $R$ 25–100 м и 1,000 на прямых. $\rho$ берётся из столбца `s_odo` карты; пока его нет, $\rho\equiv1$.
- **Возмущение $d$** — процесс Гаусса–Маркова, а не случайное блуждание:
  $$d^+=\phi d+w_d,\quad \phi=e^{-\Delta t/\tau_d},\ \tau_d=15\ \text{с},\ \mathrm{Var}(w_d)=\sigma_d^2(1-\phi^2),\ \sigma_d=0{,}10\ \text{м/с}^2,\ |d|\le0{,}8$$
  **[данные F15]** Замороженное случайное блуждание при длинном пропуске хуже, чем вообще без $d$. RMSE скорости на 10 с: 1,47 (заморозка) против 1,17 (без d) и 1,16 м/с (с затуханием τ = 10 с). На 30 с: 3,15 против 2,09 и 1,99 м/с. Затухание это устраняет.

**Дискретизация** (шаг до метки следующего события, не больше 0,05 с), $a=g\,a_d-R(v)-k_\theta\theta-k_\kappa|\kappa|+d$:

$$s^+=s+\rho(s)\big(v\Delta t+\tfrac12a\Delta t^2\big),\quad v^+=\max(0,v+a\Delta t),\quad a_d^+=a_d+(1-e^{-\Delta t/\tau})(g a^*-a_d)$$

- **Якобиан:**
  - $F_{sv}=\rho\Delta t$, $F_{sd}=\rho\Delta t^2/2$;
  - $F_{vv}=1+\Delta t\,(g\,\partial a_d/\partial v-R'(v))$, где $\partial a^*/\partial v=-xP_{max}/v^2$ в зоне мощности;
  - $F_{vd}=\Delta t$, $F_{vg}=\Delta t\,a_d$, $F_{dd}=\phi$.
- **Шум процесса.** Блок $(s,v)$: $q_a\,[[\Delta t^3/3,\Delta t^2/2],[\Delta t^2/2,\Delta t]]$.
  - **Контекстное усиление:** $q_a\leftarrow q_a\,(1+1{,}5\,e^{-t_{nc}/0{,}5\,\text{с}})$, где $t_{nc}$ — время с последней смены позиции.
  - $q_a$, $\sigma_d$, $\tau_d$ калибруются так, чтобы **предсказанная $\sigma_v(t)$ совпадала с эмпирическим ростом ошибки модели без колёс**: 0,10 / 0,23 / 0,32 / 0,48 / 0,90 м/с на 1 / 3 / 5 / 10 / 30 с (§5, п. 6).
  - Иначе ковариация врёт именно при пропусках и юзе, а ворота ориентиров перестают работать.

### 3.4 Адаптивные параметры g, k и правила заморозки (критерий 3, «адаптивная подстройка»)

- **g (масса и загрузка).** Случайное блуждание, $q_g=2\cdot10^{-5}$ с⁻¹, начальное $1{,}00\pm0{,}08$, ограничение [0,7; 1,4].
  - Данные: 30618 — 0,97; 30639 — 1,06–1,08; по отдельным бэгам 0,86–1,18.
  - После каждой стоянки > 10 с ковариация снова раздувается: $P_{gg}\leftarrow\max(P_{gg},0{,}05^2)$ — пассажирообмен.
  - Обновляется **только** при $\mu_{M0}>0{,}95$, $|u|\ge2$, $v>1$ м/с, без тревоги контроллера и без ZUPT. Иначе g — «consider»-состояние (Шмидт): строка усиления для g обнуляется, ковариация считается в форме Джозефа.
- **k (масштаб колёс).** Начальное $0\pm0{,}008$, $q_k=10^{-9}$ с⁻¹, ограничение ±2 %.
  - **Обновления по колёсам k не меняют** (Шмидт по k). k учится **только** по ориентирам через накопленную ковариацию $P_{sk}$ (§4.4).
  - Так фильтр не может «съесть» проскальзывание калибровкой масштаба (Palmer & Nourani-Vatani 2018).
- **Вектор колёс на машину неизвестен.** В топиках нет ID вагона. **[проверено]** Горизонтальная база антенн 12,442 м (30618) против 12,428 м (30639), а оценки по 3-секундному окну гуляют от 10,5 до 12,7 м. Опознать вагон по базе нельзя.
  - Поэтому общие априоры по парку плюс онлайн-адаптация g и k.
  - Цифры 12,16/12,29 м из `map_matching.md` — не длина базы. Истинная горизонтальная база 12,44 м.

### 3.6 IMM-EKF: режимы, переходы, правдоподобия

**Режимы** (динамика одинаковая, отличаются используемые измерения):
- M0 — обе тележки валидны;
- M1 — передняя недостоверна;
- M2 — задняя недостоверна;
- M3 — обе недостоверны, чистое счисление по модели.

**Правдоподобие тележки в режиме, где она объявлена недостоверной, — знаковое** (ключевой физический априор). Обозначим $\hat z=(1+k)\hat v$, $\delta=3\sqrt{S}$:

| Режим движения (по $a_d$) | $p_{bad}(z)$ | Физика |
|---|---|---|
| Тяга, $a_d>0{,}1$ | $(1-\varepsilon)\,\mathcal U[\hat z-\delta,\ \hat z+\Delta_{up}]+\varepsilon\,\mathcal U[0,30]$ | Буксующее колесо только быстрее вагона |
| Торможение, $a_d<-0{,}1$ | $(1-\varepsilon)\,\mathcal U[0,\ \hat z+\delta]+\varepsilon\,\mathcal U[0,30]$ | Юз или блокировка — колесо только медленнее |
| Выбег | $(1-\varepsilon)\,\mathcal U[\hat z-3,\ \hat z+3]+\varepsilon\,\mathcal U[0,30]$ | Сбой датчика |

Параметры: $\Delta_{up}=8$ м/с; $\varepsilon=0{,}1$ — несимметричные отказы датчика (спайк, шум, залипание).

**Почему это важно.** Показание «не по физике» (завышение в торможении, занижение в тяге) в «плохом» режиме получает только ε/30. Фильтр тогда объясняет его ошибкой **модели**, а не колёс, и сбой позиции контроллера не превращается в ложный юз с всплеском ошибки. Это закрывает аномалию «глубокий тормоз при разгоне +1,1 м/с²» (25 бэгов). Правило соответствует WSP/SCMT: в тяге истинная скорость ≤ min(колёс), в торможении ≥ max(колёс).

**Матрица переходов** (на шаг Δt, зависит от контекста; стартовые значения как в `params.hpp`):
- из M0: $p(M0\to M1)=p(M0\to M2)=\tfrac12\lambda_1\Delta t$, $p(M0\to M3)=\lambda_2\Delta t$;
- выход: $p(M_{1,2,3}\to M0)=\lambda_{rec}\Delta t$, $\lambda_{rec}=0{,}7$ с⁻¹ (естественные эпизоды расхождения тележек 0,3–2,4 с);
- базовые $\lambda_1=0{,}05\,c$, $\lambda_2=0{,}01\,c$, где $c$ — контекстный множитель:
  - 4 при $|u|\ge8$, в первые 3 с торможения при $u\le-5$ и при сработавшем CUSUM или признаке VMD (§3.7);
  - 0,2 на выбеге ($u=0$, $|a_d|<0{,}1$);
  - ×2 при $v<3$ м/с.
- Нижний предел вероятности режима $10^{-6}$.

**Цикл.** Стандартный IMM (Blom & Bar-Shalom 1988):
1. смешивание $\bar c_j=\sum_i p_{ij}\mu_i$, $\hat x_{0j}$, $P_{0j}$;
2. EKF режима;
3. $\mu_j\propto\Lambda_j\bar c_j$, где $\Lambda_j$ — произведение правдоподобий по тележкам;
4. объединение моментами.

Стоимость: 4 × EKF(5) — единицы мкс.

**Жёсткий гейт спайков.** $\nu^2/S>25$ в M0 при согласованной второй тележке ($\nu^2/S<9$) → отсчёт выброшен и посчитан, на режимы не влияет.

**Ограничения.** $v\ge0$ (проекция и нижний предел $P_{vv}$), $|d|\le0{,}8$, $g\in[0{,}7;1{,}4]$, $|k|\le0{,}02$. Ковариации в форме Джозефа с симметризацией.

**Предел наблюдаемости (честно, для питча).** В M0 фильтр на каждом шаге подтягивается к колёсам, поэтому **медленное** синхронное проскальзывание не видно в пошаговом правдоподобии IMM. Это тезис Palmer 2018: «слип — медленное расхождение, а не выброс». Для него нужен накопительный тест (§3.8). Проскальзывание, растущее медленнее ~0,3 м/с², неотличимо от ошибки модели (0,1 м/с²). Ошибка ограничена, но не нулевая (сценарий S03 — самый тяжёлый).

### 3.7 Предфильтры и FDI (до IMM)

1. **Невалидные значения** (NaN/Inf, < 0, > 110 км/ч) → отбросить, счётчик.
2. **Санитайзер меток по топику:** принять, если $s_{last}<s\le s_{last}+r\,\Delta t_{recv}+0{,}35$ с. После 8 согласованных отказов подряд — пересинхронизация. Скачок назад больше 5 с → жёсткий сброс.
   - Проверено на 122 бэгах: отброшено 0,005 %, все отброшенные — «призраки» ±1 с.
3. **Таймаут.** Нет валидного отсчёта 0,6 с → тележка «отсутствует»: нет обновления. Это **не ноль**.
4. **Залипание.** Одинаковое ненулевое значение ≥ 1,2 с, пока другая тележка или модель изменилась > 0,4 м/с → тележка недостоверна до 1 с согласия.
5. **«Ноль, когда другая едет > 5 км/ч»** → отказ датчика, а не стоянка. Данные F8: 311 отсчётов в 3 бэгах 30639.
6. **Признаки проскальзывания** (не отбраковка, а усиление матрицы переходов):
   - VMD: скользящее среднее по 3 отсчётам $|z_f-z_r|>1{,}0$ км/ч. Чистые данные: p99,9 = 0,44 км/ч. Подозревается быстрая тележка в тяге и медленная в торможении.
   - Ускорение тележки вне физики: наклон по 0,3 с выше +1,8 или ниже −3,5 м/с². Данные: p0,1…p99,9 = −1,60…+1,11 м/с².

### 3.8 CUSUM медленного синхронного дрейфа

Знаковый CUSUM по нормированной невязке M0, сброс при смене знака режима:

$$C_k=\max\!\Big(0,\ C_{k-1}+\sigma_{reg}\,\frac{\bar\nu_k}{\sqrt{\bar S_k}}-\kappa_c\Big),\qquad \sigma_{reg}=\operatorname{sign}(a_d),\ \kappa_c=0{,}5,\ h=5$$

- $\bar\nu$ — средняя невязка двух тележек.
- Тревога → множитель $c=10$ в матрице переходов к M1–M3 и заморозка g, d, k на время тревоги.
- Сработав, CUSUM «отдаёт» решение IMM, а не переключает режим напрямую: вероятности и плавность остаются в IMM.

### 3.9 Стоянка (ZUPT) и защита от блокировки колёс

- **Условие:** обе тележки свежие (возраст < 0,3 с) и < 0,15 км/ч не меньше 0,25 с **и** ($u\le0$ **или** $\hat v<1{,}2$ м/с). Датчик режет скорость ниже 0,15 км/ч, 31 % отсчётов равны 0.
- **Защита.** Если $\hat v>1{,}2$ м/с и $u<0$, нули на колёсах — это юз или блокировка (сценарий S05), а не стоянка.
- **Действие:** псевдоизмерение $v=0$ (σ = 0,003) во всех режимах; $a_d\leftarrow0$; $s$ заморожено; g и k — «consider»; d не обновляется; запуск логики ориентиров (§4.3).
- **Трогание:** снимается при $u>0$ и первом ненулевом колесе, либо через τ + 0,2 с по модели, если колёса молчат.

### 3.10 Монитор согласованности позиции контроллера

Сбои канала — около 2 % движения: «залипшая» −8 на 10–100 с; глубокий тормоз при разгоне в 25 бэгах.

- **Когда считаем:** $\mu_{M0}>0{,}9$ и $|z_f-z_r|<0{,}3$ м/с.
- **Невязка:** $r_a=\tilde a_w-\hat a_{model}$, где $\tilde a_w$ — МНК-наклон средней скорости колёс за 0,5 с.
- **CUSUM:** $G\leftarrow\max(0,G+(|r_a|-0{,}25)\Delta t)$. Тревога при $G>1{,}0$ (≈ 2–4 с расхождения > 0,4–0,5 м/с²).
- **Действие при тревоге («model_suspect»):**
  - $q_a\times10$;
  - переход в M3 запрещён ($\lambda_2\to0$);
  - g и d заморожены;
  - **предсказание к метке выхода по ускорению колёс $\tilde a_w$, а не по модели** — иначе прогноз на 0,1 с даёт систематическую ошибку до 0,26 м/с на каждом выходе;
  - WARN «controller inconsistent».
- **Снятие:** 2 с согласия.

**Таблица различения.** Модель вместе с IMM решает, кто виноват: колёса или модель.

| Наблюдение | Решение |
|---|---|
| Колёса расходятся с моделью «против физики» (выше модели в торможении, ниже в тяге) | Виновата модель или позиция → верим колёсам (знаковое правдоподобие, монитор) |
| «По физике», с рывком, VMD или ускорением вне пределов | Проскальзывание → M1/M2/M3 |
| «По физике», плавно, тележки согласны | Неоднозначно → CUSUM, умеренное доверие к обоим, без жёсткого решения |

### 3.11 Сцепление и скольжение — диагностика (бонусы критерия 3)

Все оси моторные, поэтому сцепная масса = полная масса.

- **Используемое сцепление:** $\mu_{used}=(1+\gamma)\,|g\,a_d|/g_0$, $\gamma\approx0{,}08$. Типично: 0,10 при полной тяге, 0,09 при служебном торможении, 0,18 на −15.
- **Продольное скольжение тележки:** $\lambda_i=\big(z_i/(1+\hat k)-\hat v\big)/\max(\hat v,1\ \text{м/с})$.
- **Оценка предела сцепления.** При каждом начале проскальзывания ($P>0{,}7$ в тяге или торможении): $\hat\mu_{max}\leftarrow0{,}7\hat\mu_{max}+0{,}3\,\mu_{used}(t_{onset}-0{,}3\,\text{с})$.
  - Без событий $\hat\mu_{max}$ возвращается к априору $0{,}30\cdot CK(v)/CK(0)$ с τ = 300 с (Curtius–Kniffler).
  - Класс рельса: сухо ≥ 0,22, мокро 0,12–0,22, низкое < 0,12.
- **Ограничение модели в M3.** В тяге $g\,a_d\le\hat\mu_{max}g_0/(1+\gamma)$. Не применяется при $u\le-13$: магниторельсовый тормоз не зависит от сцепления, поэтому предел правдоподобия там 3,5 м/с².
- **Флаги по тележкам.** $P_{slip,f}=\mu_1+\mu_3$, $P_{slip,r}=\mu_2+\mu_3$. Флаг включается при > 0,7 не меньше 0,2 с и выключается при < 0,3 не меньше 0,5 с. Тип: буксование ($a_d>0$), юз ($a_d<0$), отказ датчика (FDI или показание «против физики»).
- **Также публикуем:**
  - g — относительная масса ≈ $1/g$;
  - k — износ колеса, $D\approx D_{nom}(1+k)$;
  - d — эквивалентный уклон ($1000\,d/9{,}81$ ‰).

**`/diagnostics`, 2 Гц**, уровни OK / WARN / ERROR / STALE:

| Статус | Значения |
|---|---|
| `inputs` | Возраст входов, отброшенные метки, выбросы, пропуски |
| `slip` | Флаг, тип, $P_{slip,f/r}$, $\lambda_{f/r}$, CUSUM, время в M3 |
| `adhesion` | $\mu_{used}$, $\hat\mu_{max}$, класс |
| `model` | g, k, d, model_suspect |
| `localization` | Ребро, s, $\sigma_s$, число принятых и отклонённых ориентиров, время с последнего ориентира, GNSS-подписки уничтожены |
| `timing` | proc p50 / p99 / max, частота, > 100 / > 250 мс |

### 3.12 Время, сообщения не по порядку, публикация

- **Время фильтра — header-метки.**
  - Метка колеса — время измерения: сдвиг против GNSS header 0 ± 20 мс, приход на ~50 мс позже метки.
  - Метка cmd ≈ время bag (лаг 1 мс).
  - cmd — вход с удержанием значения, колёса — измерения.
- **Буфер событий** сортируется по (метка, порядок прихода). Фиксированный лаг **1,0 с**: всё старше `latest − 1,0 с` фиксируется, более поздние сообщения отбрасываются и считаются.
  - Это закрывает p99,9 задержки колёс и «залповую» выгрузку после сбоя шины.
  - Буфер на 8 с не нужен (§9).
- **`query(t)`** константная: копия зафиксированного состояния, прогон буферизованных событий ≤ t, предсказание к t.
- **Метки выхода:**
  - (а) метки cmd, 20 Гц, ≈ время bag;

### 4.2 Инициализация по GNSS (≤ 5 с по меткам, включая стартовый всплеск)

1. **Начало выходной СК** — первый фикс master (любой status ≥ 0), параметр `origin_mode`. Скорее всего, так делает скрипт судьи (`geodetic2enu(…, lat[0], lon[0], alt[0])`). Начало ENU в другом месте поворачивает оси: при смещении начала на 5 км на восток поворот ≈ 0,07°, то есть до ~6 м на расстоянии 5 км. Поэтому берём ровно первый фикс бэга.
2. **Курс ψ0** — медианный азимут вектора master → rover по сопоставленным парам с |b| ∈ [12,1; 12,8] м.
   - Разброс в окне: медиана 0,012°, p90 0,027°.
   - Запасные варианты: азимут GNSS vel при |v| > 2 м/с, затем касательная карты.
3. **Кандидаты** — точки рёбер в пределах 25 м от медианы master с $|\mathrm{wrap}(\psi_0-\psi_e)|<60°$.
   - Трамвай ходит в одну сторону, у параллельных путей курсы противоположны.
   - $J=d^2/\sigma_p^2+\Delta\psi^2/\sigma_\psi^2$ ($\sigma_\psi$ = 10°), выбор по минимуму.
   - При неоднозначности ($J_2-J_1<4$, обычно веера на конечной и не-RTK старт) держим 2 гипотезы (P2), иначе берём лучшую.
4. **$s_0$** — медиана проекций за окно (трамвай стоит); $P_{ss,0}=\max(\sigma_p^2,0{,}3^2)$, где $\sigma_p$ = 0,05 м при RTK и 2 м при status 0 (14 из 77 стартов не RTK).
5. **Сразу ориентир.** Если трамвай стоит и в воротах есть остановка с p ≥ 0,5 (конечная платформа; 73 из 77 бэгов стартуют на конечных) — сразу обновление по ориентиру.
6. $v_0$ = 0 или колёса; $g_0=1$, $k_0=0$.
7. **Уничтожить GNSS-подписки**, записать в лог «GNSS init done; subscriptions destroyed», вести счётчик проигнорированных GNSS-сообщений.
8. **Нет GNSS или нет привязки** (d > 25 м; депо — 2 из 97 бэгов): относительная одометрия от (0, 0, 0) по курсу из параметра, 2D-счисление с растущей $\sigma_{cross}$, WARN.

Результаты проверки инициализации (`analysis/map_build/cache/init_results.json`):

|---|---|---|

| Смещение 2 м | 1,2 м | 0 |
| Смещение 5 м | — | 30 % (веера на конечной) → держать 2 гипотезы при не-RTK |

### 4.3 Распространение и виртуальные балисы

- s живёт в том же EKF: $\dot s=\rho v$. На цикле main — перенос через 11 054 м. На ответвлениях по умолчанию main (§4.5).
- **Ориентир-остановка.**
  - **Триггер:** ZUPT держится ≥ 1,0 с, один раз за стоянку.
  - **Кандидаты:** кластеры с σ ≤ 3 м и p ≥ 0,3 в окне $\pm(3\sqrt{P_{ss}+\sigma_L^2}+5\ \text{м})$.
  - **Гейт:** $d^2=(s-\mu_L)^2/(P_{ss}+\sigma_L^2)<9$ **и** единственный кандидат. Два кандидата в воротах → пропуск.
  - **Обновление** всех режимов IMM: $H=[1,0,0,0,0]$, $R=\max(\sigma_L,0{,}3)^2$; скачок ограничен $3\sqrt S$.
  - Остановка «не в том месте» (очередь, светофор с широкой σ) не находит кандидата, обновления нет.
- **Коррекция на стоянке безопасна:** v = 0, скачок позиции только уменьшает ошибку. Коррекции в движении (P2, зоны скорости) размазывать по ~1 с.
- **Свидетельство** (`map_matching.md` §3.5, сырые колёса, leave-one-out по базе ориентиров, 49 рейсов):

| Режим | Вдольпутевая RMSE | Дрейф в конце |
|---|---|---|
| Только карта | 4,4 м (30618) / 17 м (30639) | 0,086 % / 0,53 % |
| Карта + остановки | 2,2 м / 6,6 м; все рейсы 2,64 м, p95 5,9 м | 0,043 % / 0,070 % |
| + масштаб по парам остановок | 30639: 4,7 м | — |

### 4.4 Калибровка масштаба колёс (ETCS по балисам) — P0

- **Механизм.** k лежит в состоянии, по колёсам это «consider»-параметр. При интегрировании $v=z/(1+k)$ накапливается ковариация $P_{sk}\approx-D\,P_{kk}$, где D — пройденный путь. Обновление по ориентиру с невязкой Δs корректирует **и s, и k**.
  - Короткие базы дают малое $P_{sk}$ и малую поправку k — это автоматически решает проблему «короткой базы», из-за которой в отчёте по карте (вариант D) масштаб разошёлся на 1,48 %.
- **Скорость сходимости.** WB: остановки 146 м (p 0,61) → 555 м → 881 м (p 0,73). После ~0,9 км $\sigma_k\approx\sqrt2\cdot0{,}3/735\approx0{,}06\%$.
- **Защиты:**
  - $|k|\le2\%$;
  - во время M3 и проскальзывания к $P_{ss}$ добавляется $(0{,}05\,\Delta s)^2$, чтобы невязку ориентира объясняла ошибка s, а не масштаба;
  - применять k-поправку только если ориентир принят гейтом.
- **Двойной эффект.** Скорость на выходе $\hat v=z/(1+\hat k)$ теряет смещение −0,08 м/с в бэгах вроде 03.09. Это критерий 1 (30 баллов), а не только позиция.

### 4.5 Ответвления — P2

- **wb_detour:** 14 % рейсов, 730 м, боковое смещение 4,2 м. По умолчанию main.
- **Опционально — детерминированный банк гипотез.**
  - На расхождении порождается гипотеза «detour» с априором 0,14.
  - Веса — по правдоподобию ориентиров, специфичных для ветки, плюс априор перехода со сглаживанием Лапласа.
  - Выход — argmax с гистерезисом (переключение при $w_{new}>2w_{cur}$).
  - Скоростной фильтр общий: у ветвей различается только отображение s → (x, y).
- **Ожидаемый выигрыш мал** (≤ 4 м поперёк на 730 м в 14 % рейсов). Фильтр частиц на 500 частиц не нужен (§9).

## 7. Дифференциаторы, ранжированные по «баллы × заметность для жюри»

1. **Виртуальные балисы и калибровка масштаба колёс по ETCS.**
   - Вдольпутевая ошибка 2–3 м, дрейф ≤ 0,05 %; норматив ETCS ±(5 м + 5 %) — ~100× запаса.
   - Одна и та же k лечит и дрейф, и смещение скорости (бэги 03.09: −1,5 %).
   - Слайд: «ошибка пути пилой — сброс на каждой остановке».
2. **Физически обоснованный знаковый IMM: «модель — виртуальный акселерометр»** (развитие акселерометрического критерия SCMT/Malvezzi без IMU).
   - Ловит синхронный юз обеих тележек (все оси моторные).
   - Не путает сбой позиции контроллера с юзом.
   - Вероятности режимов дают флаг по каждой тележке.
   - Демонстрация на S01–S05 и S19: сырые колёса против нашей оценки против GNSS, без всплесков.
3. **Карта уклонов и кривизны в динамике.** Дрейф модели без колёс вдвое меньше (10 с: 1,09 → 0,48–0,60 м/с), то есть «трамвай знает, где горка». Прямо отвечает на пункты кейса «уклон» и «кривые».
4. **Оценка сцепления и адаптация модели онлайн:** $\mu_{used}$, $\hat\mu_{max}$, класс рельса, λ по тележкам, g (масса), k (износ колеса), d (эквивалентный уклон). Всё в `/diagnostics` с уровнями — все три бонуса критерия 3.
5. **Честные ковариации:** NEES и покрытие ±1σ/±2σ на графике; σ_s растёт по ETCS и сбрасывается на балисах. Критерий 2 явно учитывает ковариации.
6. **Доказуемое реальное время:**
   - гистограмма задержки внутри ноды;
   - `latency_probe` (сопоставление по точной метке);
   - таблица соответствия в Docker с 2 CPU / 512 МБ;
   - стресс `--rate 5`, наклон RSS ≈ 0.
7. **Защита от дисквалификации:** GNSS вырезан после окна → выход побитово тот же; тест «нет будущего»: изменение входов после t не меняет выход до t.
8. **Конфигурируемый проектор СК с измеренной таблицей расхождений** (110 м / 12,4 м / 1,8 м): показывает глубину погружения.
9. **Лестница абляций с бутстрэп-CI по бэгам.** Каждый слой обязан обыгрывать предыдущий, иначе выключается.
10. (Опционально) ML-остаток поверх физики, только если выигрыш доказан на многошаговых горизонтах.

## 8. План валидации (метрики — как у судьи)

### 8.1 Конфигурация судьи-копии (`tools/harness`)

- **Эталон:** фикс master (status ≥ 0, «призраки» header починены) → ENU от первого фикса master; скорость = |v_xy| master vel.
- **Сопоставление** по ближайшей метке, допуск ±0,05 с (эталон → выход).
- **Обе гипотезы времени (J-hdr, J-bag) всегда в отчёте.** Альтернативные СК (UTM, rover, alt−alt0) — для таблицы риска.

### 8.2 Метрики

- **Скорость:** RMSE, MAE, смещение (знаковое), p95, max.
  - По всему прогону (как у судьи, со стоянками) и только в движении.
  - По режимам: разгон (a > 0,3), торможение (a < −0,3), крейсер, стоянка, отправление, прибытие, низкая скорость; по командам: тяга, тормоз, выбег.
  - По бэгам и сводно (pooled).
- **Положение:**
  - дрейф в конце % = $|e_{3D}(t_{end})|/L_{path}$;
  - вдоль пути: MEAN (знаковое), MEAN|e|, MAX, RMSE, p95;
  - поперёк пути: RMSE / MAX;
  - x / y / z RMSE, 3D RMSE;
  - дрейф по отрезкам 100–800 м в стиле KITTI (защита от «удачного финиша»).
- **Корректность Odometry:**
  - монотонные ненулевые метки, frame_id, единичный кватернион;
  - всё конечно, ковариация положительно полуопределена;
  - доля сопоставленных отсчётов ≥ 99,9 %.
- **Ковариации:** NEES по скорости и вдоль пути, покрытие ±1σ/±2σ.

### 8.3 Устойчивость

- **Матрица прогонов:** набор `tools/anomaly_sim/scenarios/suite.yaml` (S00–S19) × val × 3 сида.
  - Проскальзывание одной или обеих тележек, плато крипа, юз с WSP и блокировкой.
  - Короткие и длинные пропуски, «залповая» выгрузка, выбросы, NaN/Inf.
  - Залипание, рост шума, джиттер и перестановки меток, «призраки».
  - Износ, сбои позиции контроллера, комбинированные наборы.
  - S19 — простой набор в стиле жюри.
- **Метрики:**
  - Δ каждой метрики относительно S00;
  - max|e_v| в окнах ±10 с вокруг событий;
  - время восстановления до |e_v| < 0,2 м/с;
  - детектор: precision / recall / задержка по разметке инъекций;
  - ложные тревоги в час на S00 и природных данных;
  - число NaN и падений = 0.
- **Прогоны без GNSS (17 длинных) и короткие (11):** без падений, без расходимости, самосогласованность «модель ↔ колёса».

### 8.4 Сплиты и честность

- Решения принимаем на `val` (17). Под итоговые цифры **запечатать тест** (~6 бэгов: включить 03.09 и 30639); код не читает его до финала.
- Карта и ориентиры для валидации — `map_train`, для сдачи — `map`.
- Все числа в документах генерируются из JSON результатов одной командой (`verify`).

### 8.5 Реальное время

- **Задержка:**
  - в ноде: proc = steady(publish) − steady(recv);
  - e2e (`latency_probe`): p50 / p99 / max, счётчики > 100 и > 250 мс.
- **Частота и максимальный разрыв** выхода.
- **Ресурсы:** CPU %, RSS и его наклон (psutil) на 30-минутном бэге.
- **Прогоны:** в Docker `--cpus=2 --memory=512m --memory-swap=512m`; стресс `--rate 5`; ASan/UBSan-сборка на 1 бэге.
- **Сборка:** чистый клон → `colcon build` в `ros:humble-ros-base` с `--network=none`.

### 8.6 Лестница абляций (главный слайд «почему это работает»)

1. B2 — сырые колёса, гигиена входов.
2. + IMM (без модели).
3. + модель тяги.
4. + карта уклонов и кривизны.
5. + ZUPT.
6. + карта пути.
7. + ориентиры.
8. + k по ориентирам.
9. + знаковое правдоподобие и CUSUM.
10. + монитор контроллера.
11. (+ гипотезы на ответвлениях, + ML).

Шаги 1–6 проверяются на скорости, 6–8 — на позиции, 9–10 — на инъекциях. Каждая строка с 95 % бутстрэп-CI по бэгам.

### 8.7 Ворота приёмки перед сдачей

- **Скорость:** pooled RMSE (J-hdr, val) ≤ 0,045; |смещение| в режимах ≤ 0,02.
- **Позиция:** вдольпутевая RMSE ≤ 3 м; дрейф в конце ≤ 0,05 % (медиана), ≤ 0,2 % (худший).
- **Инъекции:** на S01–S05, S19 max|e_v| ≤ 0,8 м/с.
- **Ложные тревоги:** ≤ 0,5/ч.
- **Устойчивость:** 0 NaN, 0 падений на S18.
- **Реальное время:** частота ≥ 20 Гц; максимальный разрыв < 0,1 с; p99 задержки < 5 мс; RSS < 100 МБ.
