# Резервная одометрия трамвая — ревью решений для команды

Состояние на 26.09, вечер. Код — локальный git (`C:\MosTransHack`). Что изменилось с 25.09 — раздел 4, решения D16–D24.
Все цифры получены на **отложенных** бэгах (val, 17 шт.). Карта и модель строились только по train.

## 1. Суть решения

C++-ядро без зависимостей от ROS плюс тонкая нода ROS 2 Humble.

- **Фильтр.** Калмана, 5 гипотез о датчиках (GPB1). Прогноз — нелинейная модель тяги и продольной динамики с уклоном
  из карты. Коррекция — по двум тележкам с детекторами проскальзывания, юза, залипания и пропусков.
- **Положение.** Одномерное по нашей карте пути. Дрейф гасят «виртуальные балисы»: остановки и точки сброса тяги.
- **GNSS.** Используется только в первые секунды — для привязки. Потом нода от него отписывается.
- **Выход.** В MGRS 37U CB (x продолжается за 100 км), точка `base_link` — ось поворота передней тележки на уровне
  касания колеса и рельса (TF организаторов).

## 4. Ключевые решения

**D1. Модель тяги — таблица a\*(позиция, скорость) + инерционное звено τ = 0.452 с, без запаздывания.**
Привод отрабатывает уставку силы, а не ускорения (коэффициент при уклоне ≈ g/(1+ρ) ≈ 8). Таблица 31×21 подобрана
по ошибке открытого прогноза. Без колёс модель держит скорость с ошибкой 0.09/0.20/0.26/0.37/0.53 м/с
на горизонтах 1/3/5/10/30 с. «Держать последнюю скорость» даёт 0.54/1.49/2.29/3.81/6.00.

**D2. Уклон из карты — прямо в динамику** (k_g = 8.22/7.98/7.36 для тормоза/выбега/тяги). Без уклона ошибка
10-секундного прогноза 0.91 м/с вместо 0.60.

**D3. Состояние фильтра [s, v, d, k, g].**
- d — возмущение, асимметрично ограничено: до +0.6 м/с² под тягой (больше физически невозможно — значит проскальзывание),
  до −4 м/с² при экстренном торможении.
- g — адаптивная «масса» (у двух вагонов тяга различается на 8–10%).
- k — масштаб колеса.

**D4. k — «учитываемое» состояние Шмидта: колёса его не двигают, калибруют только ориентиры.** Из колёс и модели
наблюдаемо лишь (1+k)·g. Без этого k уплывал до +1.3% с неверным знаком.

**D5. 5 гипотез (GPB1):** норма / сбой передней / сбой задней / сбой обеих → только модель / «манёвр»
(обе тележки верны, ускорение не объясняется контроллером). Взяли GPB1, а не полный IMM: при полном смешивании
фильтр нормального режима успевал подстроиться под буксующие колёса и «перезахватывал» их (ошибка 2.1 м/с).

**D6. Правдоподобие сбоя со знаком:** под тягой проскальзывание завышает, при торможении юз занижает.

**D7. Совместное проскальзывание/юз — CUSUM Пейджа по (ускорение колеса − ускорение модели).** Отслеживаются только
физически возможные направления. При тревоге скорость и путь **откатываются** на траекторию модели от начала
аномалии, затем защёлка «только модель» до возврата колёс. Синтетика: ступенчатый совместный юз +25% —
максимальная ошибка 0.017 м/с (без механизма 2.1).

**D8. Экстренный тормоз вне контроллера — режим «манёвр».** Реальный случай `30618_616ec56b`:
RMSE скорости 0.44 → 0.028 м/с.

**D9. Прочие детекторы.**
- Скачки (> 6 м/с²), NaN, отрицательные и абсурдные значения.
- Залипание: одинаковое значение ≥ 1.2 с.
- **«Ноль при движении»**: тележка = 0, а другая > 0.5 м/с — считаем её мёртвой. Это паттерн 30639 на старте;
  раньше фильтр винил исправную тележку.
- Пропуски (0.6 с).
- Стоянка — обнуление скорости (ZUPT).
- Монитор контроллера: разгон без тяги или сильное торможение под тягой → 8 с не верим позиции рукоятки.

**D10. Карта пути (pathgraph) — своя, по GNSS обучающих прогонов.**
- Состав: основной цикл 11 053 м плюс ответвления (веер на западной конечной, объезд).
- Точность: 0.9 см медиана, p90 23 см.
- Колёса в кривых недомеряют путь (насыщение ~0.9%); поправка идёт по кривизне карты.
- Когда организаторы пришлют свою карту, сверим.

**D11. Виртуальные балисы.**
- **Остановки:** 49 мест (платформы, сигналы, конечные), разброс 0.2–0.6 м.
- **Сбросы тяги:** 4 места, где водители резко снимают тягу (n ≥ 4 → 0), видимо перед изоляторами контактной сети.
- **Ассоциация:** вероятностная, против гипотезы «случайная остановка». Обновление по s, через корреляцию s–k
  калибруется масштаб колеса.
- **Эффект:** медианная ошибка вдоль пути 6.6 → 1.5 м.

**D12. Точка и система выхода.**
- **Сдвиг до `base_link`:** +9.9 м от антенны 1. Подобран по данным: направление базы антенн в кривых совпадает
  с хордой между тележками (база 7.55 м). Невязка курса 1.6° против 14.7° при нуле.
- **Геометрия:** получается, что антенны стоят на свесах «Львёнка» — антенна 1 сзади, антенна 2 спереди.
- **Высота:** −3.0 м от антенны (TF организаторов 25.09). Проверка: эталонная z из примера организаторов на ~3.0 м ниже
  RTK-высот антенн рядом.
- **Курс:** по хорде между тележками.

**D13. Время и публикация.**
- Время — только `header.stamp`. Буфер фиксированного запаздывания 0.3 с переупорядочивает сообщения,
  front/rear с общей меткой сливаются.
- Выход — на каждой метке контроллера и колёс плюс сетка 50 мс. Метки строго возрастают, частота ~43 Гц,
  совпадение с эталоном 100%.

**D14. GNSS только в окне инициализации (5 с), затем отписка.**
- Тест доказывает, что выход побитово одинаков с GNSS после окна и без него. Это защита от дисквалификации.
- Если GNSS нет совсем — относительная одометрия от старта.

**D15. Реестр параметров — единый источник:** `params.yaml` генерируется из ядра. Тест проверяет, что каждый ключ YAML
известен ядру и каждый параметр есть в YAML. ROS 2 молча игнорирует опечатки в именах, поэтому это важно.

**D16. Время: скачки меток подтверждаются вторым сообщением.** Метка дальше +5 / −10 с от текущего времени — сбой,
если её не подтвердило второе сообщение в пределах 1 с. Подтверждённый скачок назад или вперёд ≥ 60 с — новый прогон.
Выход публикуется только на принятых метках. Раньше после 2 с тишины всех входов нода отвергала все метки навсегда.

**D17. Окно GNSS — 5 с от первого фикса; привязка на момент медианной метки фиксов** по истории пути за 30 с.

**D18. Балисы — вероятностная ассоциация (PDA)** по всем кандидатам и гипотезе «не балиса», без схлопывания σ_s.

**D19. Исправления по набору сбоев** (49 сценариев × 7 бэгов; число «разошедшихся» прогонов 53 → 8):
- тревога одной тележки считается совместной, только если вторая выбыла;
- медленная опора возмущения для CUSUM проскальзывания;
- проверка контроллера по абсолютному ускорению;
- сглаженное согласие тележек при восстановлении;
- ограничение возмущения в режиме «только модель»;
- трогание без данных колёс; перепривязка к одной живой тележке;
- залипание 0.8 с.

**D20. Опора CUSUM юза выбирается по шуму колёс.** Тормозная таблица ошибается по-разному по ходу одного торможения:
возмущение меняется от +0.7 до −0.3 м/с², пока тормоз нарастает. Медленная опора отстаёт и даёт ложный «юз» у
остановки (4 из 69 реальных прогонов, до 100 м ошибки). Поэтому при обычном шуме опора — собственное возмущение
фильтра. При шуме выше 0.1 м/с (в 4 раза выше натурального) включается медленная опора, устойчивая к шуму.
Уклон входит в опору так же, как в динамику.

**D21. Положение s не обновляется по колёсам.** Его коэффициент усиления через масштаб колеса (P_sk·v) — малая
разность двух больших величин; без балис она двигала s на 0.4–0.6 м за отсчёт (до 96 м назад за прогон без GNSS).
Путь — интеграл скорости, положение правят только балисы.

**D22. Поле невязки d(s)** — медианное необъяснённое ускорение по ячейкам 10 м, выученное по прогонам. На val
в окнах без колёс: скорость 0.732 → 0.715 м/с, путь 3.71 → 3.63 м.

**D23. Публикуемая неопределённость откалибрована по train и проверена на val:** дисперсия скорости
max(0.32·P_vv, 2.5e-4) (покрытие 95 %-го интервала 0.957); 99 %-я граница ошибки вдоль пути 5.76·σ_s (покрытие 0.989).

**D24. Точка base_link строится по оси кузова**, проходящей через обе антенны (жёсткая TF). Карта — это путь
антенны, который в петлях R ≈ 16 м уходит на ~0.7 м наружу рельсов.

**D25. Ассоциация балис с запасом на уход одометрии** (`landmark_assoc_q` = 0.008 м²/м пути с последнего фикса места).
Запас идёт только в решение об ассоциации, само обновление — с дисперсией фильтра.
- Зачем: одометрия между балисами уходит на −0.41…+0.48 % (5–95 % отрезков train), и верные балисы отвергались.
- В системе судьи: val 3-D медиана 1.14 → 0.89 м; train среднее 2.48 → 1.90 м; набор сбоев — те же 9 из 343,
  уход положения после сбоя 6.42 → 5.37 м.
- Цена: очередь в ~3 м перед платформой иногда принимается за платформу; без GNSS +2 %.
- Отвергнут шум пути в ковариации (`q_along`): 14 из 46 прогонов train хуже.

**D27. Выход выровнен по времени с эталоном судьи** (`/localization/kinematic_state` из кода проверки организаторов).
На их бэге эталон запаздывает: скорость на ~0.1 с относительно колёс, положение на 0.078 с относительно RTK. Скорость
публикуется как v − a·0.1, положение — для «метки − 0.08 с». По их коду: скорость 0.061 → 0.028 м/с.

**D28. Тупик west_arrival_2 в карте и распознавание съезда** — по шероховатости log(v_перед/v_зад) у стрелки
(главный путь 0.56–1.14 %, тупик 1.48–3.33 %, порог 1.3 %) и по месту остановки (85–135 м). По коду организаторов
положение 5.78 → 1.12 м вместе с D27; на наших 61 прогонах меняются только 3 прогона, кончающихся в тупике.

**D29. Балисы для проверки на val — только по train** (раньше кластеризация шла по train+val событиям).

**D30. Масштаб колеса по шагу квантования скорости.** Показания тележки идут ступенями q км/ч, q = c·(1 + k); c
постоянна для вагона и эпохи колёс (таблица `maps/wheel_epochs.csv`). Вагон и эпоха выбираются сами — по дате
прогона и согласию с k фильтра. Ошибка k после учёта — 0.028 % (медиана по 60 прогонам). По коду организаторов
положение 1.12 → 0.96 м, без GNSS 2.27 → 1.64 м; val 3-D 2.22 → 2.15 м (среднее), train 1.75 → 1.54 м; набор сбоев
без изменений (9 из 343).

**D31. Тупик: раннее решение при подавляющей шероховатости** (rms > 2 % от начала тупика; главный путь нигде
не выше 1.35 %). **D32. Поправка начала дуги тупика** +0.77 м (три тупиковых прогона train). Бэг организаторов
0.96 → 0.82 м, пик 9.5 → 4.5 м; val без изменений, набор сбоев тот же.

**D26. Эталон судьи для проверки: вертикаль только по мастер-антенне.** RTK-высота ровера часто ошибается на метры.
Горизонтальная ось кузова берётся по двум антеннам при согласованных фиксах. Медиана z-ошибки на val 0.48 → 0.23 м:
оценщик тот же, точнее стал эталон.

## 6. Открытые вопросы и риски

1. **TF антенн** (обещали прислать). Сдвиг 9.9 м оценён по данным. Высота 3.5 м — допущение, по z возможна ошибка до нескольких метров.
2. **Карта организаторов** обещана позже — сверить с нашей.
3. **Вертикальный датум z у эталона** (эллипсоид или геоид): неизвестен. Эксперт сказал, что z «не обязателен».
4. **Масштаб колеса на незнакомой дате.** До первого ориентира (~150–400 м) работает априор ±0.6%.
   Бэг `defd0170` (03.09, колёса −1.7%) остаётся трудным.
5. **Выбор ветки на стрелке без GNSS ненаблюдаем.** Прибытие на альтернативный путь западной конечной
   (3 из ~50 прогонов) даст ошибку в конце.
6. **Сборка ROS-ноды ещё не проверена в Docker** (ядро собирается и тестируется нативно). Слот — 27.09 до 13:00.
